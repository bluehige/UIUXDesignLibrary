# Game UI Overlay

## 추가 입력

- 장르와 핵심 플레이 루프
- 플레이 속도와 실패 비용
- 카메라와 화면 거리
- 플랫폼과 입력 장치
- 동시 표시 정보
- 세이브·네트워크 구조
- 연령 등급과 어린이 여부
- 현지화 언어
- 기존 HUD·메뉴·아트 자산

## 추가 산출물

1. 플레이 상태별 HUD 정보 우선순위
2. 입력별 포커스·버튼 매핑
3. 게임 화면 인벤토리
4. 튜토리얼 노출 규칙
5. 메뉴 복귀·세이브·오류 흐름
6. 접근성 옵션 목록
7. 실제 플레이 가독성 테스트 시나리오
8. 플랫폼별 차이표

## 플레이 상태 매트릭스

```text
상태 이름:
플레이어의 즉시 판단:
반드시 보일 정보:
필요할 때만 보일 정보:
숨길 정보:
허용 가능한 시선 이동:
입력:
실패 피드백:
복귀 지점:
```

## HUD 우선순위

```text
즉시 생존·실패
→ 현재 행동 자원
→ 단기 목표
→ 위치·방향
→ 성장·수집
→ 장식·세계관
```

HUD 정보는 상시 표시, 상황 표시, 요청 표시로 구분한다.

## 컨트롤러 검수

- 현재 포커스가 항상 명확하다.
- 방향키 이동과 시각적 배치가 일치한다.
- 포커스가 숨은 요소나 화면 밖으로 빠지지 않는다.
- 취소·뒤로 동작이 일관된다.
- 탭 전환과 버튼 아이콘이 플랫폼에 맞다.
- 마지막 포커스 위치를 합리적으로 복원한다.
- 마우스와 컨트롤러 전환 시 포커스 충돌이 없다.

## 튜토리얼 원칙

- 행동 직전에 필요한 정보만 짧게 보여준다.
- 한 번에 한 가지 행동을 가르친다.
- 이미 아는 사용자는 건너뛸 수 있다.
- 실패 후 다시 확인할 수 있다.
- 설명 문장보다 실제 조작과 즉시 피드백을 우선한다.
- 핵심 기능은 튜토리얼을 놓쳐도 메뉴에서 재학습 가능하다.

## 비주얼 노블 추가 기준

- 대사 가독성이 배경 미술보다 우선한다.
- 화자, 대사, 선택지, 시스템 메시지를 명확히 구분한다.
- 자동, 스킵, 읽은 문장 스킵, 로그, 저장·불러오기의 규칙을 정의한다.
- 선택지 전체가 조작 가능하고 결과·비용을 지나치게 숨기지 않는다.
- 대화창 숨기기와 복구 방법을 제공한다.

## 검수 질문

- 전투·탐색 중 필요한 정보가 제때 보이는가
- HUD가 세계·캐릭터·목표를 가리지 않는가
- 포커스가 항상 보이고 논리적으로 이동하는가
- 키보드·마우스·터치·컨트롤러 전환이 가능한가
- 튜토리얼이 행동 직전에 짧게 등장하는가
- 작은 TV·휴대기기·스트리밍 압축에서도 읽히는가
- 색·음향·진동 중 하나를 사용할 수 없는 사용자에게 대안이 있는가
- 저장·네트워크 오류 후 진행을 복구할 수 있는가
- 실제 플레이에서 UI 확인 때문에 시선을 과도하게 빼앗기지 않는가

## 금지

- 콘셉트 아트 한 장을 조작 가능한 UI로 취급
- 장르와 무관한 액션 HUD 적용
- 컨트롤러 포커스 없는 PC형 메뉴
- 모바일 화면에 작은 데스크톱 버튼 배치
- 모든 정보를 상시 표시
- 애니메이션 때문에 입력·피드백 지연
- 실제 플레이 장면 없이 정지 화면만 검수
