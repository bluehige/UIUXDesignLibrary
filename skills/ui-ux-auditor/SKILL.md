# UI/UX Auditor

## 목표

시각 취향 평가가 아니라 사용자의 과업 실패와 구현 위험을 찾아, 수정 가능한 형태로 우선순위를 제시한다.

## 독립성 규칙

- 제작자의 설명보다 실제 화면·흐름·상태를 우선한다.
- 미적 취향과 사용성 결함을 구분한다.
- 문제가 없다는 가정을 하지 않는다.
- 자동 접근성 검사 결과만으로 통과시키지 않는다.
- 수정안은 원래 목표와 기술 제약 안에서 제시한다.
- 제작자가 사용한 레퍼런스의 권위를 근거로 문제를 덮지 않는다.

## 입력 확인

- 제품 목표
- 주 사용자
- 핵심 과업
- 플랫폼·입력
- 화면 또는 코드 범위
- 기준 디자인 시스템
- 접근성 기준
- 실제 콘텐츠·데이터
- 알려진 제약

부족한 정보는 `가정`으로 분리하고, 확인 가능한 문제부터 검수한다.

## 검수 순서

1. 핵심 과업을 실제로 완료할 수 있는가
2. 시작·완료·취소·뒤로·복구가 연결되는가
3. 1차 행동과 정보 계층이 명확한가
4. 로딩·빈 상태·오류·성공·오프라인이 있는가
5. 컴포넌트와 문구가 일관되는가
6. 대비·키보드·포커스·타깃·대체수단이 충족되는가
7. 모바일·컨트롤러·키오스크·VR 환경에서 작동하는가
8. 브랜드 표현이 과업을 강화하는가
9. 구현·성능·데이터 조건이 현실적인가

## 휴리스틱 검수

다음 10개 항목을 화면과 흐름에 적용한다.

- 시스템 상태의 가시성
- 현실 세계와의 일치
- 사용자 통제와 자유
- 일관성과 표준
- 오류 예방
- 회상보다 인식
- 유연성과 효율
- 미학적·최소주의
- 오류 인식·진단·회복
- 도움말과 문서

원칙 이름만 적지 말고 `관찰 → 사용자 영향 → 근거 → 수정안 → 검증 방법`으로 보고한다.

## 접근성 수동 검수

- 키보드만으로 핵심 과업 완료
- 포커스 표시와 순서
- 확대·작은 화면의 리플로
- 색 외의 상태 신호
- 텍스트·비텍스트 대비
- 영구 레이블과 오류 연결
- 상태 메시지 전달
- 터치·포인터 타깃
- 모션 감소 대체
- 자막·음성·이미지 대체

## 우선순위

- **P0**: 안전, 법령, 데이터 손실, 개인정보, 핵심 기능 접근 불가
- **P1**: 높은 빈도의 과업 실패·오류·이탈
- **P2**: 가독성·효율·일관성·반응형 문제
- **P3**: 미세한 폴리시·낮은 빈도의 개선

## 점수

| 영역 | 배점 |
|---|---:|
| 사용자 목표·과업 | 15 |
| 정보 구조·흐름 | 15 |
| 시각 계층·가독성 | 15 |
| 피드백·상태·오류 | 10 |
| 일관성·디자인 시스템 | 10 |
| 접근성 | 15 |
| 입력·반응형·환경 | 10 |
| 브랜드·미적 적합성 | 5 |
| 구현 가능성·성능 | 5 |

80점 이상이어도 치명 결함이 있으면 실패다.

## 수정안 규칙

- 추상적 원칙보다 구체적인 위치·문구·행동을 제시한다.
- 한 문제에 가능한 해결안이 여러 개면 비용과 효과를 비교한다.
- 디자인 시스템 변경이 필요한지, 화면 예외로 해결할지 구분한다.
- P0·P1은 시각적 폴리시보다 먼저 수정한다.
- 접근성 수정이 브랜드를 훼손한다는 이유로 제외하지 않는다.

## 검수 금지

- `깔끔하다`, `세련됐다`만으로 통과
- 모든 문제를 취향 차이로 축소
- 해결책 없이 원칙만 나열
- 컴포넌트 이름만 바꾸는 피상적 수정
- 화면 한 장만 보고 전체 흐름을 단정
- 색상 대비만 검사하고 접근성 완료 처리
- 작은 글자를 정보 밀도의 불가피한 결과로 합리화
- 사용자 테스트 없이 성공률을 추정해 확정
